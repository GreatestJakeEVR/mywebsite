# Jake DevWorks portfolio

The Astro + TypeScript website lives at the repository root. It replaces the former Django application, which remains recoverable from Git history at commit `f4181f95873a0c83b4f849b788b89d33d3595064`. The original `design-preview/` remains the approved visual and wording reference. The homepage, Work page, blog landing page, introductory article, and Creations page build to static HTML. Shared navigation runs on every page; project interactions run on Work, and contact interactions run on the homepage. No React runtime or server adapter is shipped to website visitors. The separate Sanity Studio uses React for editing.

## Run and check

Use Node.js 22.23.4 or later (an even-numbered supported release) and pnpm 11.25.0, pinned in `package.json`. Development was verified with Node 24.22.1.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

The default development URL is `http://127.0.0.1:4321`. To check and review the actual output:

```sh
pnpm check
pnpm test
pnpm build
pnpm verify
pnpm preview
```

`check` checks Astro and TypeScript; `test` checks contact email encoding and blank input; `verify` checks all built pages, including CMS-generated blog routes, their local links and anchors, the exact approved introduction, original asset bytes, and preview indexing protections. Run `build` before `verify`.

On this Windows machine, the bundled pnpm CLI is available through Node if `pnpm` is not on PATH:

```powershell
$pnpmCli = 'C:/Users/jake/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.cjs'
$env:NODE_USE_SYSTEM_CA = '1'
$env:ASTRO_TELEMETRY_DISABLED = '1'
node $pnpmCli install --frozen-lockfile
node $pnpmCli check
node $pnpmCli test
node $pnpmCli build
node $pnpmCli verify
node $pnpmCli preview
```

The system CA option resolved the local registry certificate-chain error without disabling TLS validation. The telemetry option avoids a config write outside the workspace in the restricted environment. These are local process settings, not deployment requirements.

## Editing and architecture

- `src/pages/` defines `/`, `/work/`, `/blog/`, `/blog/welcome/`, and `/creations/`.
- `src/layouts/BaseLayout.astro` shares document metadata, fonts/styles, and the skip link. `src/components/` contains the homepage sections, header, footer, and project dialog.
- `src/data/projects.ts` contains typed project-detail copy, reused from the prototype. Published posts, projects, and services are now read from Sanity at build time; reviewed offline/seed content lives in `src/data/default-content.ts`.
- `src/scripts/navigation.ts` handles the shared menu. `src/scripts/work.ts` handles accessible project dialogs and filters on `/work/`. `src/scripts/portfolio.ts` handles homepage service selection and the email-draft fallback. `src/lib/project-email.ts` creates the encoded draft without sending anything.
- `public/assets/` preserves the original logo and portrait; `src/styles/global.css` reuses the prototype styling, including the mobile orbit-overflow fix.
- The source of approval remains `design-preview/index.html`. Its introductory wording must match the built pages exactly. Do not rewrite it during CMS migration.

## Cloudflare and launch boundary

The current output is `dist/`. The Cloudflare Pages project is named `jakeardoincom`, with production branch `master`. Leave the Cloudflare root directory blank (the repository root), install with the committed pnpm lockfile, and run `pnpm build:production`. `wrangler.jsonc` records the project name, `dist` output, and public Node/Sanity build variables documented in `CMS-SETUP.md`. Cloudflare reads this file as the configuration source; keep secrets outside it. Static Astro output can be served on Cloudflare without a runtime adapter; see the [Cloudflare Astro guide](https://developers.cloudflare.com/workers/framework-guides/web-apps/astro/).

Ordinary previews keep `noindex,nofollow` in `BaseLayout.astro`; `public/robots.txt` disallows crawling; `public/_headers` adds `X-Robots-Tag: noindex, nofollow` for Cloudflare static assets. `pnpm build:production` enables public indexing and canonical URLs and generates the production sitemap, robots policy, and headers in `dist/`; `/admin/` stays unindexed. The local Astro preview does not emulate Cloudflare's `_headers` behavior. See [Cloudflare header handling](https://developers.cloudflare.com/workers/static-assets/headers/).

The Git-integrated Cloudflare Pages project `jakeardoincom` has been created. Its first build failed while installing the former root Python requirements; the root is now the Astro app. A successful hosted deployment, publish-triggered build hook, and custom-domain routing still need verification. `pnpm build:production` prepares launch output only after real Sanity and hosted Studio settings exist; it does not deploy or change DNS.
